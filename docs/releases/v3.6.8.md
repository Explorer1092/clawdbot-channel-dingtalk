# v3.6.8 发布说明

本次 patch 版本聚焦 **繁忙会话消息不丢失**、**ask-user 上下文隔离**与 **onboarding 类型兼容**。

**最新版本入口**：[`latest.md`](./latest.md)

## 🛠 修复与稳定性

* **繁忙会话中的入站消息改为排队处理**
  * [`PR #592`](https://github.com/soimy/openclaw-channel-dingtalk/pull/592)（by @cuyua9）在同一 session 已有运行任务时串行排队新消息，并提供有界等待、忙碌提示与失败恢复，避免 `reply session initialization conflicted` 导致消息无响应。
  * 队列覆盖子 Agent 路由并将消息去重锁保持到 handler 结束；AI Card 排队提示支持完成、失败和未使用状态的回收。

* **按 session 隔离 ask-user 工具上下文**
  * [`PR #594`](https://github.com/soimy/openclaw-channel-dingtalk/pull/594)（by @Zouxxyy）将 ask-user 上下文从共享状态调整为按 session 和 run 捕获，避免并发会话之间串用投递目标。

* **保持 DingTalk onboarding 输入类型兼容**
  * [`PR #593`](https://github.com/soimy/openclaw-channel-dingtalk/pull/593) 在插件边界声明 DingTalk setup 的 `password` 字段，解除对 OpenClaw SDK 共享字段的类型依赖，同时保持 `password` 到 `clientSecret` 的运行时映射不变。Fixes #591。
